# ADR 0007：言い換えは要求時だけ・生成文は原文の代わりに置かない

日付：2026-09-15／状態：採用

## 文脈

M3で`RewriterPort`を実装する。ここまでの段(stage1〜3)はすべて**判定**で、出力はラベルとスコアだった。言い換えは初めて**生成した日本語の文をそのまま利用者に読ませる**機能で、性質が違う。

決めるべきことが2つある。

1. **いつ走らせるか**。stage3(Gemini Nano)は1件あたり数秒かかる。判定ですら全投稿には流さず`shouldRun`で絞っている(ADR 0004)のに、生成をそれより広く走らせる理由は無い
2. **生成した文をどう見せるか**。小型モデルは原文の主張をひっくり返す・原文に無い固有名詞やリンクを足す・助言や謝罪を勝手に付け足す、といった失敗をする。利用者がそれを原文だと思って読むと、**この拡張は「守るため」に誤情報を渡したことになる**

2つ目が本題である。judgeは外した判定でもカバーが1枚増減するだけだが、言い換えは外した文がそのまま利用者の理解になる。

## 決定

### 1. カバーの上のボタンで、押されたときだけ言い換える

カバーは今までどおり有害判定で出す。そこに`やわらかく読む`を足し、**押されたときだけ**backgroundへ`MSG_REWRITE`を投げる。自動では一切走らせない。

読み手が「この投稿の中身は知りたいが、その言い方は浴びたくない」と思った瞬間だけモデルが動く。フィードを流し読みしている間の計算量はM2から変わらない。

### 2. 生成文は原文の場所に置かない。カバーの中に、ラベル付きで出す

言い換えは**カバーの内側に描く**。投稿本文のDOMには触らない。原文はカバーの下に元のまま残り、`原文を表示する`でいつでも戻れる。

生成文の上には必ず`AIによる言い換え(原文ではありません)`を出す。この一行が、意味のずれに対する唯一の実効的な防御である(下の「帰結」を参照)。

### 3. 出せる文が無いときはカバーを維持する。開示に倒さない

モデルが使えない・答えが検査に落ちた・時間切れ、のいずれでも`RewriterPort.rewrite()`は`null`を返し、カバーは`言い換えられませんでした`の表示で**そのまま残る**。`もう一度試す`は出すが、勝手に原文を見せることはしない。

判定側の「失敗したら意見なし」と向きが違う点に注意する。判定は失敗しても安いほうの判定が残るだけだが、言い換えの失敗で開示に倒すと、**見たくないと言った人に原文を見せる**ことになる。

### 4. 生成文は機械検査を通してから見せる

`checkRewrite()`(`src/core/rewrite-guard.ts`)が次を却下する。却下は`null`と同じ扱いになる。

| 検査 | 却下する理由 |
|---|---|
| 空・空白のみ | 見せるものが無い |
| 正規化して原文と一致 | 言い換えていない文を「言い換え」として出すのは嘘になる |
| 長さが原文の0.3倍未満／2.0倍超(短文には40文字の猶予) | 途中で切れたか、モデルが語り出したか |
| 原文に無いURL・@アカウント・#タグを含む | 捏造のうち、機械的に確実に判定できる唯一の種類。読み手が実際に踏みうる |

### 5. 生成文は永続化しない

取得した言い換えはcontent script内の`Map`(投稿idごと)にだけ持ち、タブを閉じれば消える。IndexedDBにも`chrome.storage`にも書かない。

判定キャッシュ(ADR 0002)と同居させないのは、**生成文が原文の隣に保存されていると、後から読み返した誰か(将来の実装を含む)が原文と取り違えうる**ため。再取得のコストは、利用者が自分でボタンを押した1件ぶんでしかない。

## 却下した案

- **有害判定が出たら自動で本文を言い換え文に差し替える**：読書体験は途切れないが、(a)有害判定のたびに数秒の生成が走り、ADR 0001・0004で避けたコスト構造に戻る(b)利用者が生成文を原文だと思って読む危険が最大になる。2つ目が決定的
- **言い換えを既定オフのオプションにする**：最も安全だが、M3の成果がほとんどの利用者に届かない。カバーの内側に閉じ込め、ラベルと原文への導線を必ず置く現在の作りなら、既定で出しても過剰ではないと判断した
- **生成文をIndexedDBに保存して再訪時も使う**：決定5のとおり、原文との取り違えの危険に見合わない
- **検査に落ちた答えを、もう一度モデルに聞き直す**：待ち時間が倍になり、2回目が良くなる保証も無い。落ちたら落ちたと出して、押し直すかどうかは人に決めさせる

## 帰結

- **意味のずれは機械では検出できない**。`checkRewrite()`が拾えるのは形の事故だけで、「否定を肯定にした」「主語を取り違えた」は素通りする。ここに対する備えは、①生成文を原文の場所に置かない ②必ずラベルを付ける ③原文を常に1クリック先に置く、の3点だけであり、**設計としてそれ以上は約束しない**。READMEにも同じ温度で書く
- 言い換え用のセッションは`expectedOutputs`が`ja`になる(分類器は英語ラベルなので`en`)。ADR 0005末尾の訂正表のとおり、言語指定を省くと`NotSupportedError`が飛びうる
- 生成は判定と違い温度を下げない。`temperature: 0`は日本語として硬すぎる文を出すため、実行環境の既定に任せる
- 分類器と言い換えでGemini Nanoの基底セッションが2つになる。モデルの重みは共有されるが、常駐が増える点は実機で様子を見る
- `VERDICT_CACHE_NAMESPACE`は上げない。M3は段を足しておらず、判定の出力も変えていない(言い換えは判定経路の外側にある)
- `RewriterPort.rewrite()`の戻り値を`Promise<string>`から`Promise<string | null>`に変えた。失敗を表現できない型のままでは決定3が書けない
