# ADR 0005：Gemini Nanoアダプタの作り

日付：2026-09-15／状態：採用

## 文脈

M2でstage3(生成LLM)をChrome内蔵のGemini Nano(Prompt API)で実装するにあたり、アダプタの作りで決めるべき点が3つ出た。いずれも「端末内で完結する」というADR 0002の前提と、フィードの流速という制約から来ている。

実装前にPrompt APIの現行仕様を公式ドキュメントで確認し、ADR 0001執筆時のメモと食い違う点が見つかった(末尾に記載)。

## 決定

### 1. モデルのダウンロードは利用者が始める。拡張は勝手に始めない

`LanguageModel.availability()`が`'available'`を返さないかぎり、アダプタはセッションを作らず`null`(判定の意見なし)を返す。`'downloadable'`の状態で`create()`を呼ぶと**数GBのモデルダウンロードが始まる**ため、これをフィードの閲覧中に黙って起こさない。

ダウンロードの開始はオプション画面のボタンに置き、進捗を`downloadprogress`で表示する。回線が従量制の利用者が、SNSを開いただけで数GBを引かされることを避ける。

### 2. 1投稿ごとに`clone()`した使い捨てセッションで判定する

基底セッションはシステムプロンプトだけを持ち、判定のたびに`clone()`して使い、終わったら`destroy()`する。理由は2つ。

- **投稿どうしの混線を防ぐ**：1つのセッションを使い回すと直前の投稿が文脈に残り、次の投稿の判定が引きずられる。判定は1件ずつ独立していなければならない
- **コンテキストが伸びない**：使い回すとコンテキストウィンドウに向かって伸び続け、あふれると自動で古い対が間引かれる。基底を空のまま保てばこれが起きない(`initialPrompts`は間引きの対象外)

service workerが停止するとセッションのオブジェクトも消えるため、失敗時は基底セッションの参照を捨てて次回に作り直す。

### 3. LLMはラベルで答え、スコアは代表値に変換してから利用者の閾値に通す

小型モデルに0〜1の連続値を較正して出させるのは無理があるので、出力は`safe`/`mild`/`harmful`の3択に制約する(`responseConstraint`にJSON Schemaを渡す)。

ただし`Verdict.score`の意味は「**有害である確信度**」で、パイプラインは`score`が大きい判定を採用する。ここに「回答への自信」を入れると、**自信を持ったsafe判定がstage2のmild判定を上書きしてしまう**。そのためラベルごとの代表値(safe 0.05／mild 0.65／harmful 0.95)に変換し、その値を利用者の閾値に通して最終的なseverityを出す。閾値の設定がstage3にも効く。

## 却下した案

- **セッションを1つ使い回す**：速いが、上記のとおり投稿が混線する。判定の独立性のほうが重要
- **`availability()`が`'downloadable'`ならその場でダウンロードを始める**：利用者の同意なく数GBを使う
- **LLMに0〜1の数値を直接出させる**：較正されない数値になり、閾値設計が意味を失う

## 帰結

- 端末要件を満たさない環境ではstage3が丸ごと無効になり、M1と同じ挙動に戻る。カバー機能自体は動き続ける
- オプション画面がPrompt APIの状態を表示する唯一の場所になる。利用できない理由(要件未達)もここで示す
- `responseConstraint`が実行時に拒否された場合(未対応のスキーマキーワード)は、制約なしで問い直して本文からラベルを読む。読み取れなければ「意見なし」に倒す
- スキーマは`type`/`properties`/`enum`/`required`だけに絞った。未対応キーワードが混ざると呼び出し全体が`NotSupportedError`で落ちるため
- **段を足したらキャッシュの名前空間を上げる**。判定は本文のハッシュだけで引くので、上げないと「先にフィードを見た利用者」がstage3導入前の判定に固定される。実際にstage3を足した検証で、皮肉2件が古い判定のまま素通りした。正本は`VERDICT_CACHE_NAMESPACE`(`src/core/config.ts`)で、上げる条件はそのコメントに書いた

## ADR 0001のメモからの訂正(公式ドキュメント確認済み)

| 項目 | ADR 0001時点のメモ | 現行の正 |
|---|---|---|
| トークン残量の読み方 | `inputQuota`(約6144トークン) | **`session.contextWindow`／`contextUsage`／`measureContextUsage()`に改名**。既定値は公式に非公開なので、固定値を書かず実行時に読む |
| 拡張のmanifest | (記載なし) | permissionは**不要**。`minimum_chrome_version: "138"`だけ。期限切れの`aiLanguageModelOriginTrial`は**消す対象** |
| 空きディスク22GB | 要件 | **現在も正しい記載**。加えてVRAM 4GB超、またはメモリ16GB以上かつ4コア以上 |
| 対応言語 | ja指定可 | `en`/`ja`/`es`/`de`/`fr`。**指定を省くと非対応言語で`NotSupportedError`**が飛びうるので必ず指定する |
