# ADR 0003：描画をブロックせず「カバー→非同期判定→開示」

日付：2026-09-15／状態：採用

## 文脈

「描画前に拡張がテキストを受け取り、分析してから表示」する案は、②で数十ms・③で数秒かかる以上、Xのような流速のフィードでは体感速度が破綻する。

## 決定

描画は一切ブロックしない。content scriptのMutationObserverが投稿ノードの挿入を検知した瞬間に同期でカバーを被せ(数ms)、判定は裏で非同期に走らせ、結果に応じて開示または維持する。

モードを2つ用意する(既定はreveal-first)：

- **cover-first(fail-safe)**：挿入と同時に全投稿をカバー→安全なら開示。有害物が一瞬も見えないが、全投稿が一瞬カバーされる
- **reveal-first(fail-open)**：いったん表示→有害判定が出たらカバー。体感が自然だが、有害物が判定完了までの短時間見える

## 実装上の決定

- カバーUIはshadow DOMで隔離し、ページのCSSと干渉させない
- Xの仮想スクロールはノードを再利用するため、処理済み管理はDOMノードの`dataset`ではなく**ツイートID(status URL由来)のSet**で持ち、カバーは再挿入検知のたび冪等に適用し直す
- セレクタは`data-testid`→`role`→構造のフォールバックチェーンとし、ヒット数0をコンソール警告で検知する(XのDOM変更の早期発見)
