# ADR 0009：BYOブリッジ(ネイティブメッセージング)のプロトコルと信頼境界

日付：2026-09-15／状態：採用

## 文脈

ADR 0001が既に方針だけ決めていた。「**BYOエージェント**：ネイティブメッセージング経由でユーザ自身のClaude Code等を呼ぶ。拡張は接続口だけ提供し、精度・費用の責任を負わない」。M4はこれを実装する。

動機は2つある。

1. **Gemini Nanoの端末要件を満たさない環境が多い**(空きディスク22GB・VRAM 4GB超など)。その端末ではstage3が丸ごと無効になり、丁寧な皮肉は素通りする
2. 精度に不満がある利用者が、自分の責任で強いモデルを繋げる余地を残したい

決めるべきは、プロトコルの形と、**返ってきたものをどこまで信じるか**である。

## 決定

### 1. ホストは利用者が用意する。拡張は同梱しない

ネイティブメッセージングは拡張だけでは完結せず、端末側に実行ファイルと登録用のマニフェストが要る。これは拡張の配布物には入らない(入れられない)。

参考実装を`host/`に置き、`host/install.sh`が登録する。**登録は利用者が自分で実行する**。ブラウザの設定ディレクトリへ書き込む操作を、拡張やそのビルドが勝手に行わない。

拡張IDを固定する`manifest.key`は**入れない**。代わりに`install.sh`が拡張IDを引数に取り、`allowed_origins`をその場で書く。理由は、unpackedで読み込んだ拡張のIDはプロファイルごとに変わるが、**IDを固定する鍵をpublicリポに置く設計にしたくない**ため。ストア公開版はGoogleがIDを決めるので、そちらは公開後のIDを渡せばよい。

### 2. 既定は無効。設定で明示的に有効にしたときだけ繋ぐ

`NoBeefConfig.bridge`を追加し、既定を`'off'`とする。`'native'`のときだけ`chrome.runtime.connectNative()`を呼ぶ。

`nativeMessaging`権限は、利用者が何も設定していない状態では**一度も使われない**。ストア審査の説明もこの形にする(「利用者が自分のエージェントを繋ぐ選択をしたときだけ使う」)。

### 3. ホストからの応答は外部入力として検証する

ここが本ADRの主題である。ホストは利用者の書いたプログラムであって、拡張の一部ではない。端末内で動くからといって信用できる形式のデータが返ってくる保証は無い(壊れたJSON・欠けたフィールド・巨大な文字列・想定外のラベル)。

- **判定**：`severity`と`score`の**形と範囲**を検証してから`Verdict`にする。`score`が0〜1でない、`severity`が3値でない、といったものは`null`(意見なし)に倒す。スコアからseverityを決めるのは従来どおり`severityFor()`(`src/core/severity.ts`)で、**利用者の閾値がブリッジ経由の判定にも効く**
- **言い換え**：Gemini Nanoと**まったく同じ`checkRewrite()`**(`src/core/rewrite-guard.ts`)を通す。空・原文と同一・長さ異常・原文に無いURLやアカウントは却下する。生成元が変わっても、利用者に見せる前の関門は変えない

### 4. 応答は時間で区切る。ポートは1回のやり取りで閉じる

`connectNative()`は長命の接続だが、要求ごとに新しいポートを開き、応答を1つ受け取ったら閉じる。ホストが黙り込んでも`withTimeout()`が切る。

接続を使い回さないのは、ADR 0005でセッションを`clone()`使い捨てにしたのと同じ理由である。**1件の処理が次の1件に影響しない**ことを、状態を持たないことで保証する。

## 却下した案

- **ホストを拡張に同梱する**：ネイティブメッセージングの仕組み上できない。仮にできても、任意のプログラムを配るのはこの拡張の趣旨ではない
- **`manifest.key`で拡張IDを固定する**：`install.sh`が引数で受ければ足りる。publicリポに鍵に類するものを置く理由が無い
- **ブリッジを既定で有効にする**：ホストが無い環境で毎回接続に失敗するだけで、誰の役にも立たない
- **ホストの応答をそのまま信じる**：端末内であることは、データが壊れていないことの保証ではない。とくに言い換えは利用者が読む文そのものなので、Nano経由と同じ検査を通さない理由が無い

## 帰結

- `nativeMessaging`権限がmanifestに増える。M5の提出物では「既定で未使用」を明記する(`docs/store-submission.md`)
- ホストが返す判定は`source: 'llm'`として扱う。Nanoと同じ「生成モデルによる判定」であり、パイプライン上の位置(ADR 0004のゲート)も同じ
- 参考実装のホストは**エコーに近い最小実装**とする。実際にClaude Code等へ繋ぐ部分は利用者が書く。拡張側が保証するのは接続口とプロトコルだけ、というADR 0001の立場をそのまま形にする
- ホストは単体で試せる。`host/README.md`に、長さ接頭辞つきのメッセージを標準入力へ流して応答を見る手順を書いた。Chromeを起動しなくても壊れているかどうか分かる
