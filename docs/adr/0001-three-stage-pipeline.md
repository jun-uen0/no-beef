# ADR 0001：3段判定パイプラインとモデル戦略

日付：2026-09-15／状態：採用

## 文脈

有害コメントの検知は難易度が段階的：①明白な暴言 ②一般的な有害表現 ③放送禁止用語を含まない丁寧な皮肉・陰湿な文。1つのモデルに全部やらせると、速度(フィードの全投稿に推論)か精度(小型モデルの限界)のどちらかが破綻する。

## 決定

コストの安い順に3段のパイプラインを組み、前段で決着した投稿は後段に回さない。

1. **語彙・正規表現**(1ms未満)：曖昧さの低い直接的な暴言のみ。文脈依存の語は入れない
2. **小型分類器**(数十ms)：`onnx-community/distilbert-multilingual-toxicity-classifier-ONNX`(int8量子化136MB)をtransformers.jsで実行。textdetox 2025データセット由来で日本語を明示対応
3. **生成LLM**(数百ms〜数秒・M2以降)：②がグレー判定したものだけ(⚠ この発火条件はADR 0004が上書きした。丁寧語の皮肉は②で低スコアになるため、グレー帯だけでは③を取りこぼす)。第一候補は**Chrome内蔵Gemini Nano(Prompt API・Chrome 138+)**。理由：モデル配布が不要になり、拡張サイズと審査リスクが消える

③の代替アダプタ(優先順)：(a)WebLLMでQwen系を実行時ダウンロード(Nanoの端末要件、空き22GB等を満たさない環境向け)(b)**BYOエージェント**：ネイティブメッセージング経由でユーザ自身のClaude Code等を呼ぶ。拡張は接続口だけ提供し、精度・費用の責任を負わない。

## 却下した案

- **Qwen等を拡張に同梱**：重みはGitHubの100MB制限とストア審査(remotely hosted code)の両方で扱いが重い。内蔵AIで不要になった
- **全投稿をLLMで判定**：フィードの流速に対しレイテンシが2〜3桁足りない

## 帰結

- ②の日本語精度は未実測。不足時は日本語データ(LLM-jp-Toxicity-Dataset等)で追加fine-tuneする
- ①はfalse positiveを避けるため意図的に狭く保つ(語の追加は配布物更新で行う)
- ②のモデルはgitにコミットしない。開発時は実行時ダウンロード+ブラウザキャッシュ、ストア提出パッケージにはビルド時に取得して同梱する(実行時ダウンロードは審査落ちの実例あり)
